# three-sum：三數和為 0（排序＋two pointer＋去重）

## 題目

LeetCode 15。`nums` **沒有排序**，找出所有**不重複**的三元組 `[a, b, c]`，使 `a + b + c == 0`。

```sh
make test   # 一開始 RED 7/10，全綠＝過關（含 overflow 題，UBSan 會中止）
```

只改 `three_sum.c`；測試在 `test_three_sum.c`，編譯會開 ASan＋UBSan。

輸出規則（見 `three_sum.h`）：

- 每組內部由小到大：`[-1, 0, 1]`，不是 `[0, -1, 1]`。
- 各組之間也由小到大（字典序）。照標準解法寫，順序會自然對上。
- `out` 只放得下 `max_out` 組；超過就回傳 `-1`，**不能寫出界**。

## 這題在考什麼

一句話：**固定一個數，剩下的就是 two-sum。** 難的不是找，是**不重複**。

1. 先排序：`qsort`。
2. 每個 `i` 固定 `nums[i]`，在 `i` 右邊跑 two-sum，目標是 `-nums[i]`。
3. 時間 O(n²)：外層 n 次，每次內層 O(n)。排序的 O(n log n) 被蓋過去。

## 動手前先猜（先回答再寫）

| # | 問題 |
|---|------|
| 1 | `{-1, -1, 0, 1, 2}`：`i = 0` 和 `i = 1` 都是 `-1`，兩次會找到什麼？要怎麼跳過？ |
| 2 | `{-2, 0, 0, 2, 2}`：找到 `[-2, 0, 2]` 之後，`l`、`r` 怎麼移才不會再找到一次？ |
| 3 | `qsort` 的比較函式寫成 `return *a - *b;` 會在哪題出事？為什麼？ |

## 重要的點

| 重點 | 說明 |
|------|------|
| 三層去重 | 外層 `i`、內層 `l`、內層 `r` 都可能撞到重複值 |
| 比較函式 | `qsort` 要你提供 `int (*)(const void *, const void *)`；Java 類比是 `Comparator<Integer>` |
| 溢位 | 三個 `int` 相加，跟 two-sum 一樣要先轉 `long` |
| 不寫出界 | 寫 `out[cnt]` 之前先檢查 `cnt` 有沒有到 `max_out` |
| `int (*out)[3]` | 「指向『3 個 int 的陣列』的指標」，所以 `out[k][0..2]` 能用；不是 `int *out[3]`（3 個指標的陣列） |

## 跟 two-sum 的差別

| | two-sum（LC 167） | three-sum（LC 15） |
|-|-------------------|--------------------|
| 輸入 | 已排序 | 沒排序，自己 `qsort` |
| 答案 | 一組 index | 所有不重複的**值** |
| 找到後 | `return 1` | 存起來，**繼續找** |
| 複雜度 | O(n) | O(n²) |

## 變形題

| 題目 | 跟本題的差別 |
|------|--------------|
| LC 16 3Sum Closest | 不求等於，追蹤最接近的總和；不用去重 |
| LC 18 4Sum | 再多固定一層，O(n³)；溢位更容易（四個數） |
| LC 259 3Sum Smaller | 數「總和小於 target」的組數：找到一個 `l` 就一次加上 `r - l` 組 |
